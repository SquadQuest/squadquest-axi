# API: guests, instance_guests, instance_open_links

Guests are people a host has invited who have **no SquadQuest account**. They live in
their own tables, not in [`instance_members`](members.md), whose `member` must be a
profile. They answer through a private link served by a static page that calls the
`guest-rsvp` edge function; the host manages them with this CLI through PostgREST.

These objects are a **pilot**, added to the v1 backend on its `feat/guest-rsvp` branch
(`supabase/tables/{guests,instance_guests,instance_open_links}.sql`,
`docs/guest-rsvp.md`). Until that lands on a server, every call here fails with a
missing-table error; the CLI reports it as such, never as an empty list.

## Tables

### `guests`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid | |
| `host` | uuid → profiles | defaults to the caller |
| `name` | text | 1–100 chars |
| `phone` | text | E.164 or null; unique per host when set |
| `token` | text | 64 hex chars, generated by the database; hosts cannot write it |
| `created_at` | timestamptz | |

Hosts may insert `id, host, name, phone` and update `name, phone`. RLS: a host sees and
changes only their own guests.

### `instance_guests`

| Column | Type | Notes |
| --- | --- | --- |
| `instance` | uuid → instances | primary key with `guest` |
| `guest` | uuid → guests | |
| `status` | text | `invited` \| `yes` \| `maybe` \| `no`, default `invited` |
| `created_at`, `updated_at` | timestamptz | |

RLS: rows only on events the caller created, and only for the caller's own guests.
Deleting a guest or an event deletes its rows.

### `instance_open_links`

| Column | Type | Notes |
| --- | --- | --- |
| `token` | text | primary key, 64 hex chars, generated by the database |
| `instance` | uuid → instances | at most one open link per event |
| `created_by` | uuid → profiles | defaults to the caller |
| `created_at` | timestamptz | |
| `closed_at` | timestamptz | null while open; a closed link stays closed |
| `max_guests` | int | default 300: how many guests the link may create |
| `guests_created` | int | maintained by the server |

Hosts may insert `instance` and update `closed_at`. RLS: only on events the caller
created.

## Writing: tables, not functions

[Principle 2](../principles.md) routes every write about a person and an event through
an edge function, because that is where notifications live. Guests are the deliberate
exception: there is **no notification** for a guest (no account, no push token, and this
tool sends no texts), so a direct table write tells nobody anything it should have. The
CLI writes these tables directly with the signed-in host's session, and RLS is the
permission check.

## The guest-facing function (contract the CLI's links point at)

`/functions/v1/guest-rsvp`, no login. The CLI does not call it; it builds the links a
host hands out, which the static page turns into these calls:

| Request | Response |
| --- | --- |
| `GET ?t=<guest token>` | `{guest:{name}, host:{first_name}, events:[Event]}` |
| `POST {t, instance, status}` | same as `GET ?t` |
| `GET ?o=<open token>` | `{guest:null, host:{first_name}, events:[Event]}` |
| `POST {o, phone, name, status}` | `{created, token, guest:null, host, events:[Event]}` |

`Event` is `{id, title, start, start_max, end, location, notes, banner, event_status,
rsvp}`. Errors are `{error: bad_request | not_found | method_not_allowed | too_large |
server_error}`.

The open-link POST is phone-first: the phone is required and deduplicated per host. A
phone already on the host's list reuses that guest (`created: false`, `token: null`);
only a guest created by that request gets its token back. There is no phone
verification, so a guest the CLI lists may have been added, or had their answer changed,
by anyone holding the flyer. The full contract is in the backend's `docs/guest-rsvp.md`.

**Links**: a guest link is `<base>?t=<guests.token>`, an open link
`<base>?o=<instance_open_links.token>`, where `<base>` is the static page's URL. If
`<base>` already has a query string the parameter is appended with `&`.
